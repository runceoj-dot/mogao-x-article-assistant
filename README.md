# 墨稿 · X 文章助手

把 Markdown 和本地配图按稿件顺序写入 **X 长文章草稿**的 Chrome 扩展。适合先在 Markdown 中写好图文，再导入 X 检查、发布。

**[下载安装包 v0.1.4（测试版）](https://github.com/runceoj-dot/mogao-x-article-assistant/releases/tag/v0.1.4)**

当前通过 GitHub 分发，尚未上架 Chrome 应用商店。账号需要本身具备 X 文章编辑权限；插件不会开通该功能，也不会自动发布。

## 安装

1. 打开上方下载页，在 **Assets** 下载 `mogao-x-article-assistant-v0.1.4.zip`。不要下载 GitHub 自动生成的 `Source code (zip)`，那不是插件安装包。
2. 解压到一个以后会保留的文件夹。
3. 在桌面 Chrome 地址栏输入 `chrome://extensions/`，打开右上角「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择**直接包含 `manifest.json` 的那一层文件夹**，不要选择 ZIP 文件。
5. 在工具栏的拼图菜单中固定「墨稿 · X 文章助手」，点击图标打开侧栏。

安装后请保留解压目录。移动或删除目录会影响扩展加载。

## 怎么用

1. 登录 X，打开文章功能，**新建一篇空白文章**。
2. 打开墨稿侧栏，导入 `.md` 文件，或粘贴 Markdown。确认识别的文章标题。
3. 选择文中用到的本地图片，或选择配图文件夹；检查每张图的匹配状态。
4. 切到「预览」，检查标题、正文及图片顺序。
5. 点击「检查连接」，确认可以导入后点击「写入 X 草稿」。写入期间保持侧栏和 X 页面打开，等待完成。
6. 在 X 中检查文字、图片顺序及排版，再自行点击 X 的发布按钮。

已有标题、正文或图片的草稿会阻止导入，请使用新的空白文章。若中途失败，已经写入的内容会保留；先检查该草稿，不要在部分写入的文章中重复整篇导入。

## Markdown 配图示例

文件这样放：

```text
我的文章/
├─ 文章.md
└─ images/
   └─ photo.png
```

`文章.md` 示例：

```markdown
# 我的第一篇 X 文章

这里是开头，支持 **粗体**、*斜体*和[链接](https://x.com)。

## 一个小标题

这是配图前的段落。

![图片说明](images/photo.png)

这是配图后的段落。
```

导入 Markdown 后，选择 `photo.png` 或包含它的文件夹。看到图片「已匹配」后再写入。若同名图片存在歧义，请改用唯一文件名或明确的相对路径。

第一次可先使用仓库中的 [示例文章.md](示例文章.md) 测试文字导入，再测试自己的配图。

## 支持范围

- Markdown 文件导入、拖入、粘贴、编辑和预览。
- 从首个一级标题或基础 frontmatter 的 `title` 提取文章标题，也可手动修改。
- 标题层级、粗体、斜体、链接、列表、引用、代码块和分隔线。
- 本地 PNG、JPEG、GIF、WebP 图片，按照 Markdown 中的位置依次插入。
- 本地保存稿件、标题和已选图片，关闭侧栏后可恢复。
- 缺图、图片歧义、已有草稿内容等检查；失败时停止后续导入。

## 兼容性与限制

| 项目 | 当前情况 |
| --- | --- |
| 浏览器 | 桌面 Chrome，清单最低版本 116；建议使用已更新的 Chrome |
| 测试环境 | Windows，独立 Chromium 和真实 Draft.js 编辑器测试夹具 |
| macOS / Linux 上的 Chrome | 尚未实测 |
| Edge | 尚未实测 |
| Firefox / Safari / 手机浏览器 | 尚未适配 |
| X 功能 | 仅长文章草稿；不支持普通帖子、线程或自动设置封面 |
| 远程图片 | 不自动下载；请先保存到本地并改为相对路径 |
| 表格 | 降级为可读文本代码块，不是 X 原生表格 |

此版本自身限制：Markdown 最大 2 MB，单图最大 15 MB，所选图片总计最大 64 MB，每篇最多 25 张图。它们不是对 X 官方限制的声明。原始 HTML 作为文字处理，不执行脚本。

X 编辑器变化可能影响识别和写入。这是测试版，建议先用一篇短稿试用。现有验证包含严格类型检查、33 个单元测试、9 项浏览器场景，以及含 25 张配图的本地编辑器导入验证；这些不等同于所有 X 账号或浏览器的线上验证。

## 常见问题

**提示未找到编辑器或连接失败**：确认打开的是 X 长文章的编辑页面，并且页面已加载完成。更新插件后也要刷新 X 页面。

**提示草稿已有内容**：新建空白文章。插件不会覆盖现有文章。

**图片没有匹配**：确认已选择图片，Markdown 中的相对路径和文件名一致，没有同名歧义。远程图片链接需要先改为本地图片。

**提示正文未成功写入或上传失败**：检查 X 中已经写入的内容，保留该草稿；侧栏点击「下载诊断日志」，检查日志后通过 [Issues](https://github.com/runceoj-dot/mogao-x-article-assistant/issues) 反馈版本、Chrome 版本、操作步骤及报错。不要公开文章私密内容或未检查的日志；日志可能含文件名和页面错误信息。

## 更新

等图片上传结束、X 草稿保存后，下载新版并解压到安装目录，在 `chrome://extensions/` 点击扩展卡片的刷新按钮，然后刷新 X 文章页面。请用新的空白文章验证新版。

## 隐私与许可

稿件和配图保存在当前浏览器。点击写入时，内容交给 X 编辑器，图片由 X 上传。插件没有自建服务器、额外登录、埋点或自动发布功能。详细说明见 [隐私说明](PRIVACY.md)。
